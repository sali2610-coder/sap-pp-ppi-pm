## מה נבדק ונמצא תקין

**1. זיהוי המכשיר והמעטפת**
- `data-device` נקבע בסקריפט inline ב-`<head>` לפני הצביעה הראשונה (`app/layout.tsx`, הסקריפט מ-`lib/device.ts`), ונשאר על `<html>` אחרי hydration. `lib/device.ts` לא השתנה בענף.
- 24 הפרופילים שהכלל של הבעלים מכסה עברו, 48 טעינות. כל מחשב קיבל desktop: Windows ב-1920×1080, ‏2560×1440, ‏3840×2160 ו-3440×1440; Edge במסך 4K בהגדלת 200% ו-300% של מערכת ההפעלה (1920×1080 ב-DPR 2, ‏1280×720 ב-DPR 3); זום 200% ו-400%; מחשב נייד עם מסך מגע (10 נקודות, 1366×768 ו-834×600); Mac עם Chrome ועם Safari; Linux; ChromeOS. כל iPad קיבל tablet: Safari עם user agent של Mac ומגע אמיתי ב-834×1112, ‏1366×1024 ו-1024×1366, ‏user agent ישן של iPad, ‏Chrome ל-iPad. טאבלט Android ב-800×1280 קיבל tablet. כל טלפון קיבל phone: 390, ‏320, ‏844×390 לרוחב ו-Android ב-412.
- המעטפת מתאימה למכשיר בכל 52 הטעינות. במחשב: רייל וסרגל עליון, בלי `.nx-mtop` ו-`.nx-mtabs`, ושני כפתורי ה-Dock ב-`#nx-dock-slot`. בטלפון ובטאבלט: להפך, והכפתורים ב-`#nx-dock-mslot` בגודל 44×44. הכפתורים נשארים ב-slot הנכון אחרי ניווט בצד הלקוח (שלושה מעברים ברייל, שניים בגיליון הניווט בטלפון). 0 שגיאות קונסולה.
- טאבלט Android במצב "אתר למחשב" (user agent של X11) מקבל desktop, בהתאם למדיניות.
- הערה לכלי הבדיקה: `shell-check.mjs`, ‏`home-check.mjs` ו-`vitals.mjs` לא קובעים `maxTouchPoints`. iPad שנבדק עם `hasTouch` בלבד מסווג desktop, ולכן הכלים האלה לא בודקים את מסלול הטאבלט.
