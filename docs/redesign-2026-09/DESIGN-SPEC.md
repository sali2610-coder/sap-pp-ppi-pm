# Design Specification · Project NEO

28.09.2026. מסמך דרישות שאינו תלוי בכיוון. הערכים של הכיוון שנבחר (צבעים, גופנים, מספרים) נקבעים ב־`TOKENS.md`; כאן נקבעים התפקידים, החוקים ומבנה כל משפחת מסכים.

## 1. תפקידי המערכת

### צבע

| תפקיד | Tokens | חוק |
|---|---|---|
| קרקע ומשטחים | canvas, surface-1, surface-2, surface-raised, overlay | לא שחור מוחלט ולא לבן מסנוור לשטחים גדולים; מצב לילה מעוצב בנפרד |
| טקסט | ink-1 (ראשי), ink-2 (משני), ink-3 (מושתק), ink-inverse | ink-1 ו־ink-2 לפחות 4.5:1 על כל משטח; ink-3 רק לטקסט ≥14px ולפחות 4.5:1 |
| קווים | line-1 (מפריד), line-2 (גבול רכיב), line-strong | מפרידים לפני כרטיסים |
| פעולה | action, action-hover, action-press, action-ink | אדום המותג; פעולה ראשית אחת בולטת למסך |
| קישור | link, link-visited | נבדל מצבע הפעולה ומסומן גם בקו תחתון בגוף טקסט |
| מיקוד ובחירה | focus-ring, select-bg, select-line | טבעת מיקוד 2px לפחות, ניגוד 3:1 מול שני הצדדים |
| מצבים | info, success, warning, danger (+ bg, line, ink לכל אחד) | תמיד עם סמל וטקסט |
| סטטוס S/4 | keep, change, replace, removed, verify | חמישה מצבים קבועים, סמל + מילה + צבע; אותו צבע לא משמש למודול |
| רמת אימות | verified, partial, requires-verification, conflict | סמל וצורת קו (רציף, מקווקו, כפול) ולא רק צבע |
| מודולי SAP | mod-* | זהות בלבד (שבב, קו צד בתרשים); כל שבב נושא גם את קוד המודול בטקסט; אין סגול; מובחנים גם בעיוורון צבעים דרך הטקסט והמיקום |
| קוד ומזהים | code-bg, code-ink | משטח עדין, לא בלוק כהה בתוך מסך בהיר |
| תרשימים | chart-1..n, edge-verified, edge-unverified | נבדלים בגוון ובבהירות, וקשר לא מאומת מקווקו |

### טיפוגרפיה

| תפקיד | גודל מינימלי | הערה |
|---|---|---|
| כותרת מסך שער | 32–44px | אחת לעמוד |
| כותרת מסך עבודה | 24–32px | לא משתלטת על הכלים |
| כותרת מקטע | 18–22px | |
| גוף קריאה | 16–18px, גובה שורה 1.65–1.8 | רוחב 60–72 תווים |
| גוף ממשק | 14–15px | רשימות, טבלאות, טפסים |
| מידע משני, תגיות | 12–13px | לא פחות מ־12px, אף פעם לא 10px |
| מזהה SAP | גופן טכני, LTR מבודד | שורה משלו בכותרת רשומה, עם העתקה |

אין tracking על עברית. אין Uppercase אנגלי לקישוט. משקלים: 400, 500, 600, 700 בלבד.

### מרווח, רשת, צורה ועומק

- סולם ריווח בבסיס 4: 4, 8, 12, 16, 20, 24, 32, 40, 48, 64.
- רשת: ניווט צד קבוע במחשב; תוכן עד 1,360px בעמודי עבודה, טור קריאה עד 72 תווים; בתצוגות גדולות מנצלים מקום לעמודות נוספות ולא לשורות ארוכות.
- רדיוס: 2, 4, 6 ו־8 פיקסלים לכל היותר; עיגול מלא רק לנקודה, לאווטאר או לכפתור אייקון עגול במובהק. כפתורים מלבניים.
- גבול: 1px; קו מודגש 2px לבחירה ולמיקוד.
- עומק: שלוש רמות בלבד (שכבה צפה, תפריט, דיאלוג). כרטיס סטטי בלי צל.
- אייקונים: lucide-react בלבד, קו אחיד, 16/20/24px; כפתור אייקון מקבל שם נגיש.

### תנועה

Tokens: micro 100ms, state 160ms, transition 240ms, complex 400ms, signature עד 1,000ms. עקומות: יציאה מהירה, כניסה מרוסנת, קפיץ עם overshoot קטן. transform ו־opacity בלבד. כל רגע חתימה נבנה עם מצב סטטי מלא ל־Reduced Motion, נעצר כשהטאב לא פעיל, ולא מעכב קלט. לכל היותר שני רגעי חתימה למסך.

### מצבים

| מצב | דרישה |
|---|---|
| ריק | משפט אחד שמסביר מה חסר ופעולה אחת (נקה מסננים, חזור לרשימה) |
| טעינה | שלד בגודל התוכן הסופי, בלי קפיצת layout |
| שגיאה | מה קרה, מה אפשר לעשות, ניסיון חוזר; לא הודעה טכנית גולמית |
| הצלחה | משוב קצר ליד הפעולה (הועתק, נשמר), גם לקורא מסך |
| לא מקוון | הודעה ברורה; התוכן הסטטי נשאר נגיש |
| מידע חסר | "לא מתועד במאגר" ולא שדה ריק או ניחוש |

### מצבי תצוגה ומסכים

יום, לילה, Reduced Motion, מובייל (320–430), טאבלט (768–1112), מחשב (1280–1920), מסך גדול (2560+), מצב הצגה, זום 200% ו־Reflow של 400%. במובייל לא מקטינים מחשב: ניווט תחתון, מסננים ב־Sheet, טבלה רחבה עם גלילה פנימית בלבד.

## 2. משפחות מסכים

| משפחה | גלוי מיד | Progressive Disclosure | הערות |
|---|---|---|---|
| בית | משפט זהות אחד, חיפוש, כניסות למודולים, תהליכים, טבלאות, טרנזקציות, ספרים ושיטות עבודה, "להמשיך" אם יש מצב שמור | מבנה המאגר, מדדים מפורטים, הסבר איך המאגר נבנה | רגע החתימה: מפת הידע |
