# v4 Open Decisions — החלטות שדורשות את Sali

רק החלטות שאי-אפשר לענות עליהן ע"י בדיקת הריפו. כל השאר נענה ב-audit. ממוין לפי נחיצות לצעד הראשון.

---

## חוסם התחלה (צריך תשובה לפני E0/D0)

### D1. אישור המסמך + עקרונות-העל
v4 מבקש (§18.1–4): אישור v4 כמסמך היחיד והמחייב (מחליף v2/v3); אישור "One Design Language" כעמוד-תווך שווה ל-Knowledge Preservation; אישור מבנה שכבת Presentation (§9); אישור מיזוג UX Judge → Design Judge.
**נדרש:** כן/לא לכל אחד. *(המלצה: מאשר — ה-audit הראה שהכל כבר קיים דה-פקטו, רק לא מפורמל.)*

### D2. פורמט ה-Truth Layer — הכרעה ארכיטקטונית
היום ה-Truth הוא `data/*.ts` מוקלד (עובד, נבנה מ-xlsx). v4 מבקש `registry/` JSON + `manifests/`. שתי דרכים:
- **(A) הגירה מלאה** ל-`registry/*.json` + סכימה — נאמנות מלאה ל-v4, אבל נוגע במקור הנתונים של כל האתר.
- **(B) שכבת-סכימה מעל ה-TS הקיים** — ולידציה ב-build בלי להזיז קבצים; פחות טהור, סיכון מינימלי, Evolution אמיתי.
**נדרש:** בחירת A או B. *(המלצה: B — Evolution לא Rewrite; אפשר להעביר ל-A בעתיד אם צריך.)* זו ההחלטה הכי משמעותית בכל התוכנית.

### D3. נעילת ערכי הטוקנים והקטלוג (v4 §18.5)
אחרי D0 (מיפוי) — נעילה סופית של `design/tokens.json` + `design/components.json`. הערכים ייגזרו 1:1 מ-`app/globals.css` הקיים (95 vars), אבל **הנעילה עצמה היא נקודת-האישור העיצובית המרכזית שלך** — מרגע זה design-lint אוכף אותם.
**נדרש:** אישור הרשימה שתוצג ב-D0. גם: מה עושים עם ~25 ה-hex הקשיחים שנמצאו בקומפוננטות (`page-help.tsx`, `process-flow.tsx`, `object-expert.tsx`) — להמיר לטוקנים? *(המלצה: כן, ב-D2.)*

## חוסם המשך (צריך תשובה לפני E3–E4)

### D4. בחירת פיילוט E3
ה-audit ממליץ **IDocs** (doc נפרד). v4 מציע "IDocs / פרק PP-PI".
**נדרש:** אישור IDocs, או בחירה אחרת.

### D5. Component Registry + approval-workflow (סיכון גבוה)
היום ~129 קומפוננטות בלי `components.json` ובלי workflow לאישור וריאנטים. v4 §9.15 דורש שקומפוננטה/טוקן חדשים יעברו אישור שלך.
**נדרש:** אישור העיקרון "כל קומפוננטה/טוקן חדש עובר אישור Sali; הסוכנים לא משנים על דעת עצמם" + מי מאשר deprecation.

### D6. Preview + Rollback strategy
היום אין Preview env ואין Rollback פורמלי; כל פרסום בונה `out/` מחדש. v4 §12 רוצה Preview per-PR + Rollback בדקה + artifact versioning.
**נדרש:** (א) איפה מתארחים ה-Previews (Vercel preview / GitHub Pages / אחר)? (ב) לאשר "פרסום רק דרך G4, אין עקיפה ידנית".

## עתידי — Roadmap עם תאריך או "מתוכנן" (v4 §18.7)

### D7. Runtime AI (E6)
"הסבר לי" / עוזר-חיפוש / מנתח-תקלות — עונה רק מ-Registry עם ציטוט; הפלטפורמה עובדת 100% בלעדיו. `copilot.tsx` + `gemini.ts` קיימים כשלד.
**נדרש:** עתידי-מתוכנן, או Roadmap עם תאריך? האם מותר קריאת LLM חיצוני (סותר "100% offline" — צריך הכרעה מפורשת)?

### D8. Dark Mode (D5)
מיפוי Theme שני על הטוקנים, אפס שינוי בקומפוננטות.
**נדרש:** רוצה בכלל? אם כן — אחרי E5.

### D9. Monitoring / Analytics
היום רק `@vercel/analytics` בסיסי. v4 §13 רוצה ניטור זמינות + מגמות Lighthouse + דשבורד. ל-Academy/reader — טלמטריה אופציונלית (מה נלמד, streak).
**נדרש:** מותר טלמטריה אנונימית (בלי מעקב משתמשים)? זה נוגע לפרטיות ולכן החלטה שלך, לא של הריפו.
