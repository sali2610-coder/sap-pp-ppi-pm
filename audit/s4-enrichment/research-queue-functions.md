### catalog-integrity finding (2026-09-21, measured during the batch-3 inventory)

`data/function-intel.ts` carries five keys that are not ABAP function modules, and the
coverage report counts every one of them as a row of the `functions` catalog:

| key | what it actually is | already covered elsewhere |
|---|---|---|
| `MATMAS` | IDoc message type | yes, `idoc:msg:MATMAS` in `data/verification/idocs.ts` |
| `LOIPRO` | IDoc message type | yes, `idoc:msg:LOIPRO` in the same file |
| `BOMMAT` | IDoc message type (marked `inferred: true`) | no |
| `Control Recipe` | a PP-PI process concept, not a callable object (`inferred: true`) | no |
| `PPCC1` | process-message concept (`inferred: true`) | no |

Consequences, all measured: the functions catalog total (145) is inflated by five;
MATMAS and LOIPRO are double-counted across two catalogs under two different id kinds;
and `Control Recipe` cannot receive a canonical `fm:` id at all, because the id syntax
rule in `lib/evidence/validate.ts` rejects a space.

Not fixed inside an enrichment batch. Removing or re-homing rows in `function-intel.ts`
changes what the cockpit renders on the function pages, so it belongs in its own audited
change with its own before/after route check, not as a side effect of writing overlay
records.
