## Problem
דוח צריכות חו"ג לפק"עות ייצור **ZPP_PORD_CONS** (אתר 500) נפתח **ריק** — לא מציג פקעות/שורות. קרה **לכמה משתמשים**, לא רק אחד.

## Symptoms
- כניסה לדוח → טבלה ריקה.
- **עורך → מחק סינון** → הנתונים מופיעים.
- בכניסה הבאה — שוב ריק (הסינון חוזר).

## Root Cause
לדוח שמורה **פריסת ALV ברירת-מחדל (ככל הנראה גלובלית) עם סינון (filter) פעיל** שמסתיר את כל השורות. הנתונים נטענים אך מוסתרים. "מחק סינון" מנקה **זמנית בלבד** ולא משנה את הפריסה השמורה — לכן חוזר. העובדה שקורה לכמה משתמשים מצביעה על **default גלובלי**.

## Evidence
- Transaction ZPP_PORD_CONS, אתר 0500, מודול PP (מתוך תיאור התקלה).
- מסך ALV ריק; תפריט **עורך** מציג "מחק סינון"; אחרי הפעלתו — הנתונים מוצגים (צילומים).
- דווח שהבעיה אצל עוד משתמשים.

## Resolution
1. **עורך → מחק סינון** (נתונים מוצגים).
2. **הגדרות → פריסה → שמור** → סמן **"פריסה ראשונית"**, ו**בטל "ספציפי למשתמש"** לשמירה **גלובלית** (דורש הרשאת S_ALV_LAYO).
3. **הגדרות → פריסה → ניהול** → אתר את הפריסה הישנה עם הסינון → הסר ממנה סינון או בטל דגל ברירת-מחדל.
4. תוצאה: הדוח נפתח עם פריסה נקייה כברירת-מחדל, לכל המשתמשים.

## Prevention
- כשמקימים דוח ALV לשימוש רב-משתמשי — לשמור **פריסת default גלובלית נקייה** מראש.
- לא לשמור סינונים תפעוליים בתוך פריסת ברירת-המחדל הגלובלית.
- הרשאת תחזוקת פריסות גלובליות (S_ALV_LAYO) מרוכזת אצל גורם אחראי.

## Lessons (נשמרו ב-`../lessons/pp-pi.md`)
1. דוח ALV שנפתח ריק + "מחק סינון" מציג נתונים = **סינון בפריסה**, לא סלקציה/הרשאה.
2. "מחק סינון" זמני; התיקון הקבוע = **שמירת פריסה נקייה כ-default**.
3. בעיה אצל כמה משתמשים = **פריסה גלובלית** → תקן את ה-default הגלובלי (S_ALV_LAYO), לא אישית.

## Self Evaluation
- **מה עבד:** זיהוי מהיר ש"מחק סינון מציג נתונים" ⟵ סינון בפריסה, והבחנה בין תיקון זמני לקבוע.
- **מה עדיין לא אומת:** האם למשתמש/מטפל הרשאת S_ALV_LAYO לשמירה גלובלית — אם לא, נדרש Basis/מורשה.
- **הסלמה:** רק אם חסרה הרשאת תחזוקת פריסות גלובליות.
