# Runbook · חסימת הרשאה לטרנזקציית Z לפי מפעל — "אינך מורשה להשתמש בטרנזקציה" · Security / PP-PI

**מתי:** משתמש מקבל **"אינך מורשה להשתמש בטרנזקציה `Z...`"** — טרנזקציה Z שקיימת ועובדת לחלק מהמשתמשים/מפעלים אבל **חסומה לאחרים**. שכיח בהקמות/בדיקות Brown Field כשה-Role לא הורחב לכל האתרים.
**מודולים:** Security · Basis-touchpoint · PP-PI/PP (הכלי עצמו).
**קשור:** `authorization-missing.md` (הרנבוק הכללי — SU53/STAUTHTRACE/PFCG).

## העיקרון — הרשאה, לא באג
אם הטרנזקציה **עובדת אצל אחרים** (מפעל/משתמש אחר), היא **תקינה**. השורש הוא **הרשאה חסרה** אצל המשתמש/המפעל שנחסם — או **חוסר הקצאת Role**, או **ערך מפעל (Werks) חסר** ב-Role.

**הרשאה נבדקת לפי מפעל / הקצאת Role — לא לפי סוג הייצור (בדיד/תהליכי).** אל תסיק מסוג הייצור מי אמור להיות מורשה; זה מוכרע ע"י ערכי ה-org וה-Role בלבד.

## אבחון (ראיה חד-משמעית)
1. **SU53** מיד אחרי השגיאה אצל המשתמש שנחסם:
   - נכשל **`S_TCODE`** על שם הטרנזקציה → **חסר Role/הקצאה** → הקצה את ה-Role שמכיל את ה-tcode.
   - נכשל **אובייקט מפעל** (Werks — למשל org level ב-Role) → **הוסף את המפעל** לערכי ה-org ב-Role.
2. **STAUTHTRACE** (ST01) אם SU53 לא חד-משמעי — הפעל, שחזר, קרא את האובייקט שנכשל.
3. השווה ל-**Role של משתמש/מפעל שכן מורשה** — מזהה מיד מה חסר.

## טיפול (PFCG / הקצאה)
1. `SU53` → זיהוי החוסר.
2. `PFCG` — או **הוסף את המפעל החסר** לערכי ה-org, או ודא ש-`S_TCODE` כולל את הטרנזקציה.
3. `SU01/SU10` — הקצה את ה-Role למשתמש/קבוצה; **generate profile + user comparison (PFUD)**.
4. שחזר אצל המשתמש — הטרנזקציה נפתחת.

## שורש-על (למנוע חזרה)
כלי Z ל**כל האתרים** — לוודא שה-Role כולל את **כל המפעלים הרלוונטיים** בהקמה, לא רק את אתר הפיילוט. בבדיקות BF תחת לחץ זמן, החוסר הזה חוזר אתר-אחר-אתר; עדיף להרחיב מראש.
